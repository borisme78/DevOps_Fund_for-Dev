# Віртуалізація: основне

Конспект уроку «Virtualization»: основи, VirtualBox, Vagrant.

---

## 1. Проблема: «один сервер = один застосунок»

Раніше кожен застосунок (MySQL, MongoDB, Redis, Nginx, Apache) ставили на окремий фізичний сервер, співвідношення **server : application = 1 : 1**.

### Мінуси підходу з фізичними серверами
- Дорого купувати й обслуговувати залізо
- Погано масштабується
- Складно тиражувати (скопіювати середовище)
- Складно зробити резервування
- Вразливий до аварій заліза
- Процесор здебільшого простоює (завантаження близько 10%)
- Може знадобитися ліцензія на ОС для кожного сервера

### Мінуси запуску багатьох застосунків на одній машині
- **Конфлікти версій бібліотек:** App v1 і App v2 вимагають Lib v1, а App v2.1 і App v3 потребують Lib v1.1 та Lib v2. Усі разом на одній ОС не працюють.

### Плюси (для повноти)
- Легко зрозуміти й розгорнути
- Легко робити бекап
- Підходить для будь-якого застосунку

## 2. Рішення: віртуалізація

**Віртуалізація** дозволяє запустити кілька ізольованих віртуальних машин (VM) на одному фізичному комп'ютері. Це робить **гіпервізор**.

```
┌────────┬────────┬────────┬────────┐
│  App   │  App   │  App   │  App   │
│  VM    │  VM    │  VM    │  VM    │
├────────┴────────┴────────┴────────┤
│            Гіпервізор             │
├───────────────────────────────────┤
│  Фізична машина (CPU, RAM, Disk)  │
└───────────────────────────────────┘
```

Завантаження заліза зростає з ~10% до ~80%: 10 застосунків на 1 фізичній машині замість 10 машин.

### Переваги
| Перевага | Суть |
|---|---|
| **Ефективність ресурсів** | максимальне використання потужності заліза |
| **Простіше керування** | VM це програмно визначені об'єкти, ними керують політиками й скриптами |
| **Менше простоїв** | збій ОС або застосунку зачіпає лише одну VM |
| **Швидше розгортання** | не треба купувати й налаштовувати залізо під кожен застосунок |
| **Економія та екологія** | менше серверів, менше енергії, менші витрати, менший вуглецевий слід |

## 3. Основні терміни

| Термін | Значення |
|---|---|
| **Гіпервізор** (VMM, virtual machine monitor) | ПЗ, прошивка або апаратура, що створює й запускає віртуальні машини |
| **Host** (хост) | комп'ютер, на якому працює гіпервізор |
| **Guest** (гість) | віртуальна машина |
| **VM** | ізольований «комп'ютер у файлах» з власною ОС |

### Два типи гіпервізорів

| | **Тип 1** (native, bare metal) | **Тип 2** (hosted) |
|---|---|---|
| Працює | **безпосередньо на залозі** | **поверх хостової ОС** |
| Хостова ОС | не потрібна | потрібна |
| Продуктивність | вища | нижча (додатковий шар) |
| Призначення | сервери, дата-центри | ПК розробника, навчання |
| Приклади | VMware ESXi, Proxmox, KVM, Xen, Hyper-V | **VirtualBox**, VMware Workstation Player |

```
Тип 1:                   Тип 2:
 VM  VM  VM               VM  VM  VM
  └──┬──┘                  └──┬──┘
 Гіпервізор               Гіпервізор
     │                        │
   Залізо                Хостова ОС
                              │
                            Залізо
```

### Популярні гіпервізори
Xen, Linux KVM, Microsoft Hyper-V, VMware ESXi (безкоштовний), Oracle VirtualBox, VMware Workstation Player, OpenVZ, Lguest, Xvisor, SmartOS.

Для Mac на чипах Apple (M1, M2): **Xen Project, QEMU, VirtualBox** (на момент слайдів VirtualBox для Arm64 був developer preview).

## 4. Види віртуалізації

Віртуалізувати можна не лише сервер:

- **Desktop** (робочий стіл)
- **Network** (мережа)
- **Storage** (сховище)
- **Data** (дані)
- **Application** (застосунок)
- **Data center** (дата-центр)
- **CPU / GPU**
- **Linux**, **Cloud**

### Віртуальні сервери
- Сервер «інкапсулюється» подалі від заліза: ОС, застосунки й дані стають **просто файлами**.
- Один хост може вміщати багато віртуальних серверів, а віртуальний сервер може обслуговуватися кількома хостами.
- Можна створювати **шаблони** для швидкого клонування однакових серверів.
- Віртуальні сервери можна **мігрувати** між хостами.
- Втрата одного хоста не зачіпає сервери, якщо середовище побудоване правильно.
- Хости можна додавати й виймати для обслуговування майже без простою.

> Слайд про «типи VM» змішує різні поняття: Windows/Linux/Mac VM це повноцінні ОС у гіпервізорі, а **Java VM** та **Python VM** це програмні середовища виконання коду, які не мають стосунку до гіпервізорів.

## 5. Oracle VirtualBox

Безкоштовний (GPLv3) гіпервізор **типу 2**. Працює на Windows, macOS, Linux, Solaris.

**Завантаження:** https://www.virtualbox.org/wiki/Downloads

### Що розглядається на уроці
1. Встановлення Ubuntu Linux у VM
2. Налаштування мережі (NAT, Host-only, Port forwarding)
3. Створення snapshots (знімків)
4. Логи
5. Putty (SSH-клієнт для Windows)

### Параметри VM (приклад зі слайда)
- ОС: Ubuntu 64-bit
- Пам'ять: 2048 МБ
- Диск: файл `.vdi` (10 ГБ)
- Мережа: 2 адаптери (NAT і Host-only)

> Після оновлення VirtualBox рекомендовано оновити й **Guest Additions** (драйвери для гостьової ОС). **Extension Pack** додає підтримку USB 2.0/3.0 та інші функції.

### Snapshot (знімок)
Збереження стану VM у конкретний момент. Дозволяє швидко відкотитися, якщо експеримент зламав систему.

## 6. Мережа у VirtualBox

Кожна VM має до 4 мережевих адаптерів. Кожному задається режим підключення:

| Режим | Що це | Коли використовувати |
|---|---|---|
| **NAT** | VM ходить в інтернет через хост; ззовні (з хоста) VM **не видно** | вихід в інтернет за замовчуванням |
| **Bridged** (проміжний адаптер) | VM підключається до реальної мережі як окремий пристрій, отримує IP від вашого роутера | коли VM має бути видимою в локальній мережі |
| **Host-only** (лише головний адаптер) | мережа лише між хостом і VM, без інтернету | зв'язок хост ↔ VM |
| **Internal** (внутрішня мережа) | VM бачать лише одна одну | ізольовані лабораторні стенди |
| **NAT Network** | як NAT, але VM бачать одна одну | кілька VM + доступ в інтернет |
| Not attached | мережа відключена | |

### Типова зв'язка: NAT + Host-only
- **Адаптер 1 (NAT):** інтернет у VM (оновлення, `apt install`)
- **Адаптер 2 (Host-only):** ви підключаєтесь до VM по SSH з хоста

### Port Forwarding (переадресація портів)
У режимі NAT хост не бачить VM напряму, тому налаштовують правила: «звернення на порт хоста → порт у VM».

| Назва | Протокол | Порт хоста | IP гостя | Порт гостя | Призначення |
|---|---|---|---|---|---|
| Rule 1 | TCP | **2222** | 10.0.2.15 | **22** | SSH |
| Rule 2 | TCP | **8080** | 10.0.2.15 | **80** | веб-сервер |

```bash
ssh -p 2222 user@127.0.0.1     # SSH у VM через переадресований порт
# у браузері: http://localhost:8080  → піде на порт 80 у VM
```

- `10.0.2.15` це стандартна адреса VM у NAT-режимі VirtualBox (приватний діапазон `10.0.0.0/8`).
- Порт хоста обирають понад 1024, щоб не потрібні були права адміністратора.

### Додаткові параметри адаптера
- **MAC-адреса:** генерується автоматично, є кнопка для перегенерації (потрібно, коли клонуєте VM, щоб не було дублікатів)
- **Cable Connected:** віртуальне «підключення кабелю»
- **Тип адаптера:** Intel PRO/1000 MT Desktop (за замовчуванням)

### Діагностика на хості
```cmd
ipconfig /all
```
Показує віртуальний адаптер *VirtualBox Host-Only Ethernet Adapter*. На слайді в нього адреса `169.254.x.x`, тобто **link-local** (автоконфігурація): адаптер не отримав адресу від DHCP. Це ознака того, що DHCP-сервер Host-only мережі не працює або вимкнений.

## 7. Vagrant

**Vagrant** це утиліта командного рядка для керування **життєвим циклом віртуальних машин**. Описуєте VM у текстовому файлі (**Vagrantfile**), і середовище піднімається однією командою. Це підхід **Infrastructure as Code**.

Підтримує з коробки **VirtualBox, Hyper-V, Docker**. Інші середовища підключаються через **providers**.

**Навіщо:** однакове середовище для всієї команди, відтворюваність («у мене працює»), швидке створення й видалення VM.

### Встановлення (Ubuntu)
```bash
wget -O- https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list

sudo apt update && sudo apt install vagrant
```
Для інших ОС: https://developer.hashicorp.com/vagrant/downloads

### Основні команди

| Команда | Дія |
|---|---|
| `vagrant init ubuntu/focal64` | створити `Vagrantfile` (проєкт) для образа (box) |
| `vagrant up` | створити й запустити VM |
| `vagrant ssh` | підключитися до VM по SSH |
| `vagrant halt` | зупинити VM |
| `vagrant destroy` | видалити VM |

Також корисні: `vagrant status` (стан), `vagrant reload` (перезапуск з новим Vagrantfile), `vagrant provision` (повторно запустити налаштування).

### Vagrantfile
```ruby
Vagrant.configure('2') do |config|
  config.vm.box = 'ubuntu/focal64'
  config.vm.network "forwarded_port", guest: 8080, host: 8080
end
```

| Рядок | Значення |
|---|---|
| `config.vm.box` | базовий образ VM (box) |
| `forwarded_port` | переадресація порту (те саме, що Port Forwarding у VirtualBox) |

### Плагіни
```bash
vagrant plugin install vagrant-vbguest   # автоматичне оновлення Guest Additions
```

Документація: https://developer.hashicorp.com/vagrant/docs

| Що таке snapshot? | збережений стан VM для відкату |
