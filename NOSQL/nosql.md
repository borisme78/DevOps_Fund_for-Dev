# NoSQL, MongoDB та міграції: основне

Конспект до практичної роботи: MongoDB через `mongosh` і Compass, міграції реляційної бази через `dbmate` та знайомство з Bytebase.

---

## 1. Що таке NoSQL

**NoSQL** (часто розшифровують як *Not Only SQL*) — група баз даних, які використовують моделі зберігання, відмінні від реляційних таблиць.

| Модель | Як зберігає дані | Приклад |
|---|---|---|
| **Документна** | Документи з полями, вкладеними об’єктами й масивами | MongoDB |
| **Ключ–значення** | Значення, доступне за унікальним ключем | Redis |
| **Сімейства стовпців** | Рядки з наборами стовпців, організованими для певних запитів | Cassandra |
| **Графова** | Вузли та зв’язки між ними | Neo4j |

NoSQL не означає відсутність структури, індексів чи транзакцій. Можливості та гарантії залежать від конкретної СУБД.

### MongoDB і реляційна база

| Реляційна база | MongoDB |
|---|---|
| База даних | База даних |
| Таблиця | Колекція |
| Рядок | Документ |
| Стовпець | Поле |
| Первинний ключ | Поле `_id` з унікальним значенням у колекції |

Це приблизна відповідність: документи можуть містити вкладені об’єкти й масиви, а документи однієї колекції можуть мати різні поля. Для контролю структури можна налаштувати валідацію.

## 2. MongoDB: сервер, shell і GUI

| Інструмент | Роль |
|---|---|
| **MongoDB Server (`mongod`)** | Зберігає дані та обробляє запити |
| **MongoDB Shell (`mongosh`)** | Клієнт для роботи з сервером через команди |
| **MongoDB Compass** | Графічний клієнт для перегляду й редагування даних |

`mongosh` і Compass підключаються до сервера; сам запуск клієнта не запускає сервер MongoDB.

Команда в терміналі для підключення до локального сервера:

```bash
mongosh "mongodb://127.0.0.1:27017"
```

**Типовий порт MongoDB — `27017`.** Якщо сервер працює у VM, `127.0.0.1` на Mac означає Mac. Для прямого підключення до VM потрібна її адреса та налаштований мережевий доступ.

### Вибір бази в `mongosh`

```javascript
show dbs
use borys
db
show collections
```

`use borys` перемикає поточну базу. Якщо її ще немає, вона з’явиться після створення колекції або першого запису даних.

## 3. Колекції, документи та BSON

**Документ** — набір полів і значень. MongoDB зберігає документи у форматі **BSON**, який підтримує, зокрема, вкладені структури, дати й `ObjectId`.

Навчальний приклад документа книги:

```javascript
{
  title: "Лісова пісня",
  author: "Леся Українка",
  pages: 128,
  year: 1911,
  quantity: 5
}
```

Значення тут демонстраційні. Поля `pages`, `year`, `quantity` записані як числа, а `title` та `author` — як рядки.

Якщо під час вставлення не вказати `_id`, він буде згенерований автоматично, зазвичай як `ObjectId`. `_id` ідентифікує документ і не змінюється звичайним оновленням.

Колекцію можна створити явно:

```javascript
db.createCollection("books")
```

Або вона створиться під час першого вставлення документа через `db.books.insertOne(...)`.

## 4. CRUD: додавання та читання

**CRUD** — Create, Read, Update, Delete: додавання, читання, оновлення та видалення даних.

### Create: додати документи

Команди виконуються всередині `mongosh` після `use borys`:

```javascript
db.books.insertOne({
  title: "Лісова пісня",
  author: "Леся Українка",
  pages: 128,
  year: 1911,
  quantity: 5
})

db.books.insertMany([
  {
    title: "Тіні забутих предків",
    author: "Михайло Коцюбинський",
    pages: 160,
    year: 1911,
    quantity: 3
  },
  {
    title: "Кайдашева сім’я",
    author: "Іван Нечуй-Левицький",
    pages: 192,
    year: 1879,
    quantity: 7
  }
])
```

Повторне виконання цих вставлень створить нові документи з новими `_id`, навіть якщо решта полів однакові. Приклади вставлення наведені в [документації MongoDB](https://www.mongodb.com/docs/manual/reference/method/db.collection.insertmany/).

### Read: знайти документи

```javascript
// Усі документи
db.books.find()

// Книги за конкретний рік
db.books.find({ year: 1911 })

// Один документ
db.books.findOne({ title: "Лісова пісня" })

// Лише назва й автор, без _id
db.books.find({ year: 1911 }, { title: 1, author: 1, _id: 0 })

// Сортування за роком: від новіших до старіших, до 5 результатів
db.books.find().sort({ year: -1 }).limit(5)

// Виклик форматованого виведення з практичної роботи
db.books.find().pretty()
```

Перший аргумент `find()` — **фільтр**, другий — **проєкція**, тобто вибір полів. Для сортування `1` означає зростання, `-1` — спадання. У `mongosh` результати вже форматуються; [`.pretty()` не змінює їх відображення](https://www.mongodb.com/docs/v8.0/reference/method/cursor.pretty/), як це було у старому shell `mongo`.

### Оператори фільтрації

| Оператор | Значення | Приклад фільтра |
|---|---|---|
| `$gt` / `$gte` | Більше / більше або дорівнює | `{ quantity: { $gt: 3 } }` |
| `$lt` / `$lte` | Менше / менше або дорівнює | `{ year: { $lt: 1900 } }` |
| `$ne` | Не дорівнює | `{ quantity: { $ne: 0 } }` |
| `$in` | Одне зі значень | `{ year: { $in: [1879, 1911] } }` |
| `$or` | Хоча б одна умова | `{ $or: [{ year: 1911 }, { quantity: 7 }] }` |

Кілька полів у фільтрі поєднуються умовою **AND**:

```javascript
db.books.find({ year: 1911, quantity: { $gte: 3 } })
```

Докладніше про читання даних — у [документації MongoDB](https://www.mongodb.com/docs/manual/reference/method/db.collection.find/).

## 5. CRUD: оновлення та видалення

### Update: змінити поля

```javascript
db.books.updateOne(
  { title: "Лісова пісня" },
  { $set: { quantity: 10 } }
)

db.books.updateMany(
  { year: 1911 },
  { $inc: { quantity: 1 } }
)
```

- **`updateOne()`** оновлює один документ, який відповідає фільтру.
- **`updateMany()`** оновлює всі документи, які відповідають фільтру.
- **`$set`** задає значення поля, **`$inc`** збільшує числове значення на вказану величину.
- **`matchedCount`** показує кількість знайдених документів, **`modifiedCount`** — кількість фактично змінених.

Для точного вибору конкретного документа використовують його `_id`: назва книги може повторюватися. Приклади операторів — у [документації MongoDB про оновлення](https://www.mongodb.com/docs/manual/reference/method/db.collection.updateone/).

### Delete: видалити документ

```javascript
db.books.deleteOne({ title: "Кайдашева сім’я" })
```

`deleteOne()` видаляє один збіг, `deleteMany()` — усі збіги. Порожній фільтр `{}` відповідає всім документам: `deleteMany({})` очищує колекцію. Це відрізняється від `db.books.drop()`, який видаляє саму колекцію та її індекси. Див. [видалення документів у MongoDB](https://www.mongodb.com/docs/manual/reference/method/db.collection.deleteone/).

## 6. MongoDB Compass та індекси

У практичній роботі Compass використовується для перегляду бази `borys`, колекції `books`, документів та індексів.

Фільтр у Compass має ту саму форму, що й перший аргумент `find()`:

```javascript
{ year: 1911 }
```

**Індекс** допомагає швидше знаходити дані за певними полями. Він займає місце та додає роботу під час вставлення, оновлення й видалення документів.

```javascript
// Переглянути індекси
db.books.getIndexes()

// Створити індекс за роком
db.books.createIndex({ year: 1 })
```

У звичайній колекції MongoDB автоматично створює унікальний індекс за `_id`. Індекси для інших полів обирають відповідно до запитів застосунку.

## 7. Міграції реляційної бази через dbmate

**Міграція** — версійована зміна схеми або даних. У цій практичній роботі `dbmate` працює з **MariaDB/PostgreSQL**, окремо від MongoDB.

Команди в терміналі для MariaDB з уже встановленим `dbmate`:

```bash
# Підставити власні облікові дані навчальної бази
export DATABASE_URL='mysql://USER:PASSWORD@127.0.0.1:3306/staging'

dbmate new create_users
```

Для MariaDB використовується схема URL `mysql://`. Пароль у URL потребує URL-кодування спеціальних символів.

У згенерованому файлі `db/migrations/<timestamp>_create_users.sql`:

```sql
-- migrate:up
CREATE TABLE users (
    id INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL
);

-- migrate:down
DROP TABLE users;
```

Цей SQL призначений для MariaDB; у PostgreSQL синтаксис автоматичної генерації `id` інший.

| Команда | Дія |
|---|---|
| `dbmate up` | Створити базу за потреби й застосувати незастосовані міграції |
| `dbmate status` | Переглянути стан міграцій |
| `dbmate rollback` | Відкотити останню застосовану міграцію |
| `dbmate dump` | Оновити файл схеми |

Версії застосованих міграцій зберігаються в `schema_migrations`. Файл `db/schema.sql` описує схему, а не резервну копію даних; для його генерації потрібна відповідна утиліта дампа СУБД. Відкат наведеного прикладу видаляє `users` разом із даними.

Перевірка у клієнті MariaDB:

```sql
USE staging;
SHOW TABLES;
DESCRIBE users;
SELECT * FROM schema_migrations;
```

У практичній базі також може бути таблиця `tasks` з попередніх міграцій. Міграція вище створює лише `users`.

Деталі команд і налаштувань — в [офіційній документації dbmate](https://github.com/amacneil/dbmate).

## 8. Для чого потрібен Bytebase

**Bytebase** — платформа для керування змінами та доступом до баз даних. Вона надає спільний інтерфейс для перевірки SQL, погодження змін і перегляду історії дій. Опис можливостей — в [офіційній документації Bytebase](https://docs.bytebase.com/introduction/what-is-bytebase).

| Інструмент | Основна роль у цій роботі |
|---|---|
| **mongosh / Compass** | Робота з документами MongoDB |
| **dbmate** | Застосування SQL-міграцій із файлів |
| **Bytebase** | Організація процесу змін баз даних у команді |

У практичній роботі розглянуто запуск Bytebase та логи ініціалізації PostgreSQL. Самі логи ініціалізації ще не підтверджують успішне виконання міграцій у цільовій базі.
