# Вступ до ОС та Linux: основне

Конспект уроку «Intro to Operating System / Linux Introduction» (DevOps Fundamentals for Developers).

---

## 1. Операційна система (ОС)

ОС керує апаратним забезпеченням і надає програмам середовище для роботи. Без ОС комп'ютер це «меблі».

**Дві головні родини:**
- **Windows** (Windows 11, Windows Server 2022)
- **Unix-подібні (\*nix)**: Linux, macOS, BSD

**CLI / консоль** це програма для введення команд і отримання системних повідомлень (командний рядок).

## 2. Windows: коротко

### Як відкрити командний рядок
- `Win+R` → `cmd`
- Пошук у меню «Пуск» → `cmd.exe`
- Файл `C:\WINDOWS\system32\cmd.exe`

### Найпоширеніші команди CMD

| Команда | Що робить |
|---|---|
| `dir` | список файлів і папок |
| `cd` | змінити каталог |
| `copy` / `move` / `del` | копіювати / перемістити / видалити файл |
| `md` / `rd` | створити / видалити каталог |
| `cls` | очистити екран |
| `ipconfig` | мережеві налаштування (IP, шлюз) |
| `help` | довідка по командах |
| `shutdown /s` | вимкнути ПК (`/r` перезавантажити) |
| `start` | запустити програму |

### PowerShell
Розширювана оболонка від Microsoft на базі .NET: поєднує **мову сценаріїв** з інструментами автоматизації та керування конфігурацією. Потужніша за CMD.

## 3. Чому Linux

- **Безкоштовна** й **open source**
- Переважна більшість серверів в інтернеті працює на Linux
- Усі суперкомп'ютери з Top 500 працюють на Linux
- Android побудований на ядрі Linux
- Майже все ПЗ безкоштовне, не потрібні «кряки»

### Коротка історія
- **1991:** фінський студент **Лінус Торвальдс** оголосив ядро Linux
- **1992:** ядро перейшло на ліцензію **GNU GPL**, з'явилися перші дистрибутиви
- Далі: Android, Ubuntu та інші дистрибутиви стали масовими

## 4. Linux vs Windows: головні відмінності

| Linux | Windows |
|---|---|
| Немає букв дисків (A:, C:), єдине дерево від `/` | Диски `C:`, `D:` |
| Роздільник шляху `/` | `\` |
| Імена файлів і каталогів **чутливі до регістру** (`File` ≠ `file`) | Нечутливі |
| Суперкористувач **root** | Administrator |
| Повністю **багатокористувацька** ОС | Переважно однокористувацька |
| Багато графічних оболонок (GNOME, KDE...), можна без GUI взагалі | Одна GUI-підсистема |
| Право виконання визначає атрибут `x` | Розширення (`.exe`, `.bat`, `.cmd`, `.com`) |

## 5. Структура каталогів

| Каталог | Призначення |
|---|---|
| `/` | кореневий каталог (початок усього) |
| `/bin/` | базові системні команди |
| `/etc/` | конфігураційні файли системи |
| `/home/` | домашні каталоги користувачів |
| `/lib/` | спільні системні бібліотеки |
| `/media/` | точки монтування змінних носіїв (флешки, CD) |
| `/var/` | змінні дані: логи, дані служб |

**Ідея:** у Linux «все є файл». Більшість команд це теж програми-файли в `/bin/` та інших каталогах. Більшість команд мають багато **ключів** (опцій), які змінюють їхню поведінку.

## 6. Основні команди (must know)

### Навігація та файли

| Команда | Що робить |
|---|---|
| `cd <dir>` | перейти в каталог |
| `cd ..` | на рівень вище |
| `cd /` | у корінь |
| `cd ~` | у домашній каталог |
| `ls`, `ls -al` | список файлів (`-a` приховані, `-l` докладно) |
| `touch <file>` | створити порожній файл |
| `mkdir <dir>` | створити каталог |
| `rm <file>` | видалити файл |
| `rm -i <file>` | видалити з підтвердженням для кожного |
| `rm -r <dir>` | видалити каталог з вмістом (рекурсивно) |
| `rmdir <dir>` | видалити **порожній** каталог |
| `cp src dst` | копіювати (`-r` для каталогів) |
| `mv src dst` | перемістити або перейменувати |
| `cat <file>` | вивести вміст файлу |
| `more <file>` | переглядати посторінково |
| `echo $PATH` | вивести змінну середовища |
| `clear` | очистити термінал |

### Система та довідка

| Команда | Що робить |
|---|---|
| `man <cmd>` | довідка про команду |
| `sudo <cmd>` | виконати від імені root |
| `su <user>` | змінити користувача |
| `uname -a` | архітектура й ядро |
| `lscpu` | інформація про CPU |
| `ps` | запущені процеси |
| `top` | процеси в реальному часі |
| `ip addr show` | мережеві адаптери |
| `id` | інформація про поточного користувача |

### Вимкнення й перезавантаження (потрібен root)

| Команда | Що робить |
|---|---|
| `shutdown -h now` | вимкнути (синонім `poweroff`) |
| `shutdown -r now` | перезавантажити |
| `shutdown -c` | скасувати запущене вимкнення |

> Ці команди просто надсилають сигнали запущеним програмам, тому незбережені файли можуть бути втрачені.

### Посилання (links) та inode

- Кожен файл має ідентифікатор **inode** (дивитись: `ls -i`).
- **Жорстке посилання** (hard link): ще одне ім'я для того самого inode.
  ```bash
  ln original-file added-file
  ```
- **Символічне посилання** (symlink): окремий файл-«ярлик», що вказує на шлях.
  ```bash
  ln -s original-file added-file
  ln -s today weather
  ```

| | Hard link | Symlink |
|---|---|---|
| Вказує на | inode | шлях |
| Якщо видалити оригінал | дані лишаються доступні | посилання «зламається» |
| На каталоги / між файловими системами | ні | так |

## 7. Встановлення програм

Linux використовує **репозиторії** (аналог Google Play / App Store): офіційні репозиторії дистрибутива та сторонні.

Встановлювати ПЗ може лише root (або користувач через `sudo`).

| Родина | Дистрибутиви | Інструменти |
|---|---|---|
| **Debian** | Debian, Ubuntu, Linux Mint | `apt`, `dpkg` |
| **RedHat** | RHEL, CentOS, Fedora | `yum`, `rpm` |

```bash
sudo apt install nginx      # Debian/Ubuntu
sudo yum install nginx      # RedHat/CentOS
```

## 8. Запуск програм

- У Windows запускаються файли з розширеннями `.exe`, `.com`, `.bat`, `.cmd`.
- У Linux розширення **не визначає** можливість запуску. Вирішує лише атрибут **`x`** (execute).
- Запуск файлу з поточного каталогу:
  ```bash
  ./program.sh
  ```

Якщо отримуєте `Permission denied` при запуску скрипта, потрібно додати право виконання: `chmod +x program.sh`.

## 9. Pipes та перенаправлення вводу/виводу

### Pipe (конвеєр) `|`
Передає вивід однієї команди на вхід іншої.

```bash
Command_1 | Command_2
ps aux | grep apache       # знайти процеси apache
ls -a | grep myfile        # файли, що містять "myfile" в імені
```

### Перенаправлення виводу

| Запис | Дія |
|---|---|
| `cmd > file` | записати вивід у файл (**перезаписує**) |
| `cmd >> file` | **дописати** у кінець файлу |

```bash
uname -a > mysystem.info   # результат піде у файл, а не на екран
```

## 10. Користувачі та групи

Усі \*nix системи багатокористувацькі. Кожен користувач належить до груп. У користувачів і груп є **ім'я** та **числовий ідентифікатор** (UID / GID).

### Де зберігається інформація

| Файл | Вміст |
|---|---|
| `/etc/passwd` | користувачі (ім'я, UID, домашній каталог, оболонка) |
| `/etc/shadow` | хеші паролів (читає лише root) |
| `/etc/group` | групи |

### Перегляд
```bash
id vivek        # інформація про користувача з групами
groups vivek    # групи користувача
grep developers /etc/group   # чи існує група
```

### Створення груп і користувачів

```bash
groupadd developers                 # нова група
useradd vivek                       # новий користувач
useradd -m vivek                    # + створити домашній каталог
useradd -s /bin/bash -d /home/newname -m newname   # з оболонкою і каталогом
passwd vivek                        # задати пароль
```

### Групи: ключі `-g`, `-G`

| Команда | Результат |
|---|---|
| `useradd -g developers tony` | **первинна** група |
| `useradd -G admins,ftp,www jerry` | **додаткові** групи |
| `usermod -a -G ftp tony` | **додати** до додаткової групи (`-a` обов'язково, інакше замінить усі) |
| `usermod -g www tony` | змінити первинну групу |

### Блокування й пароль
```bash
chage -d 0 username          # примусово вимагати зміну пароля
usermod -L username          # заблокувати (або passwd -l)
usermod -U username          # розблокувати (або passwd -u)
```

### Доступ до sudo

| Дистрибутив | Група | Команда |
|---|---|---|
| CentOS / RedHat | `wheel` | `usermod -aG wheel username` |
| Ubuntu / Debian | `sudo` | `usermod -aG sudo username` |

Перевірка:
```bash
su - username
sudo whoami      # має вивести: root
```

## 11. Права доступу до файлів

### Модель прав
Права задаються для трьох категорій: **owner** (власник), **group** (група), **other** (решта). Кожна має три біти: **r** (read), **w** (write), **x** (execute).

```
-  rwx  r-x  r--
│   │    │    └── other: тільки читання
│   │    └─────── group: читання + виконання
│   └──────────── owner: все
└──────────────── тип файлу
```

### Перший символ у `ls -l` (тип)

| Символ | Тип |
|---|---|
| `-` | звичайний файл |
| `d` | каталог |
| `l` | символічне посилання |
| `p` | іменований канал (named pipe) |
| `c` | символьний пристрій |
| `b` | блоковий пристрій |

### Числова (абсолютна) форма `chmod`

| Значення | Право |
|---|---|
| **4** | read (r) |
| **2** | write (w) |
| **1** | execute (x) |

Права суммуються для кожної категорії:

```
chmod 755 file
      │││
      ││└─ other: 5 = 4+1 = r-x
      │└── group: 5 = 4+1 = r-x
      └─── owner: 7 = 4+2+1 = rwx
```

| Код | Права | Типове використання |
|---|---|---|
| `755` | rwxr-xr-x | програми, каталоги |
| `644` | rw-r--r-- | звичайні файли |
| `600` | rw------- | приватні ключі |
| `777` | rwxrwxrwx | небезпечно, уникайте |

### Символьна (відносна) форма `chmod`
Попередні права враховуються, змінюється лише вказане.

| Категорія | Дія | Право |
|---|---|---|
| `u` власник | `+` додати | `r` читання |
| `g` група | `-` забрати | `w` запис |
| `o` решта | `=` задати | `x` виконання |
| `a` всі | | |

```bash
chmod u+w file       # власнику додати запис
chmod ug+r file      # власнику і групі додати читання
chmod a+x file       # всім додати виконання
chmod +x script.sh   # зробити скрипт виконуваним
```

### Зміна власника

```bash
chown new_owner file1 file2         # змінити власника
chgrp sales /home/sales/*           # змінити групу
chown -R tony:www *                 # власник і група, рекурсивно
```

### «Темний каталог» (execute без read)
Право `x` на каталог дозволяє **заходити** в нього, а `r` дозволяє **бачити список** файлів.

```bash
mkdir darkcat
chmod a-r+x darkcat      # заборонити читання, дозволити вхід
cp myfile darkcat
cd darkcat
ls -l                    # Permission denied (списку не видно)
cat myfile               # працює, якщо знаєте ім'я файлу
```

### SUID та SGID
Розширюють привілеї: програма виконується з правами **власника** (SUID) або **групи** (SGID) файлу, а не користувача, що її запустив.

Приклад: `/usr/bin/passwd` має прапор `s`, тому звичайний користувач може змінити свій пароль (який зберігається у файлі `/etc/shadow`, недоступному для запису), бо команда виконується від root.

```bash
ls -l /usr/bin/passwd    # -rwsr-xr-x  (s замість x)
```

### Спільна папка: SGID і sticky bit

**Задача:** користувачі `dev` і `test` мають спільно працювати в одній папці.

```bash
groupadd developers
useradd -m -G developers dev
useradd -m -G developers test
mkdir /home/shared
chgrp developers /home/shared
chmod 770 /home/shared
chmod g+s /home/shared      # SGID: нові файли успадковують групу каталогу
```

**Sticky bit** на каталозі: видаляти файли може лише їхній власник (як у `/tmp`).

```bash
chmod +t /home/shared       # або chmod o+t
```

> У слайдах для sticky bit написано `chmod g+t`. Коректно `chmod +t` або `o+t`: sticky bit це біт «other», а `g+s` це SGID.

## 12. SSH і авторизація за ключами

**SSH** (Secure Shell) це захищене віддалене підключення до серверів. За замовчуванням **TCP-порт 22**. Використовує асиметричне шифрування (пара ключів: **приватний** і **публічний**).

### Налаштування за ключами

```bash
# 1. Згенерувати пару ключів
ssh-keygen -t rsa -b 4096
# (приватний: ~/.ssh/id_rsa, публічний: ~/.ssh/id_rsa.pub)

# 2. Скопіювати публічний ключ на сервер
ssh-copy-id user@192.168.50.50
# або вручну:
cat ~/.ssh/id_rsa.pub | ssh user@192.168.50.50 "cat >> ~/.ssh/authorized_keys"

# 3. Підключитися
ssh -i ~/.ssh/id_rsa user@192.168.50.50
```

**Конфігурація сервера:** `/etc/ssh/sshd_config`, параметр `AuthorizedKeysFile .ssh/authorized_keys`.

### Важливо
- **Приватний ключ нікому не передавати** (права `600`). На сервер копіюється лише публічний.
- У слайдах є приклад із DSA (`-t dsa -b 1024`). Цей алгоритм застарілий і небезпечний. Сучасний вибір: **RSA 4096** або **Ed25519** (`ssh-keygen -t ed25519`).
- Це та сама технологія, що використовується для `git` через SSH (GitHub, GitLab) і для доступу до серверів AWS.
