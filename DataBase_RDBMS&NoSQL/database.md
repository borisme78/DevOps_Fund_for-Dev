# Бази даних: короткі нотатки

## 1. Основні поняття

| Термін | Що означає |
|---|---|
| **База даних (DB)** | Організоване сховище даних |
| **СУБД (DBMS)** | Програма для зберігання та керування даними: MariaDB, PostgreSQL, MongoDB |
| **Таблиця** | Дані про певні об’єкти, наприклад користувачів |
| **Рядок (record)** | Один запис: конкретний користувач або товар |
| **Стовпець (field)** | Властивість запису: ім’я, пошта, ціна |
| **SQL** | Мова для створення структури та роботи з даними в реляційних СУБД |

У нашій роботі: **UTM** запускає VM, **Ubuntu** є її ОС, **MariaDB** керує базами, **DBeaver** є графічним клієнтом, а **Tabby** — терміналом для виконання команд.

## 2. Реляційні бази та NoSQL

| | Реляційні (RDBMS) | NoSQL |
|---|---|---|
| Модель даних | Таблиці зі зв’язками | Документи, ключ–значення, графи тощо |
| Структура | Визначені стовпці та типи | Залежить від моделі; часто гнучкіша |
| Приклади | MariaDB, MySQL, PostgreSQL | MongoDB, Redis, Neo4j |
| Типові задачі | Замовлення, платежі, облік товарів | Документи, кеш, пошук зв’язків |

**MariaDB** — реляційна СУБД, що походить від MySQL. Вони мають багато спільного, але не повністю взаємозамінні. **NoSQL** — група різних підходів; транзакції та гарантії узгодженості залежать від конкретної СУБД.

## 3. Типи даних та обмеження

| Запис у MariaDB | Для чого |
|---|---|
| `INT` | Цілі числа, наприклад ідентифікатори |
| `VARCHAR(100)` | Рядок довжиною до 100 символів |
| `DECIMAL(10,2)` | Точне десяткове число: 10 цифр загалом, 2 після крапки; підходить для ціни |
| `DATE` / `DATETIME` | Дата / дата й час |
| `PRIMARY KEY` | Унікально визначає рядок, не допускає `NULL` |
| `AUTO_INCREMENT` | Автоматично генерує числовий ідентифікатор |
| `NOT NULL` | Значення обов’язкове |
| `UNIQUE` | Забороняє дублікати значень; у MariaDB допускає кілька `NULL` |
| `FOREIGN KEY` | Контролює посилання на запис в іншій або цій самій таблиці |

**NULL** означає відсутнє або невідоме значення. Це не нуль і не порожній рядок. Перевірка: `IS NULL`, а не `= NULL`.

## 4. Базові SQL-команди

Команди виконуються у клієнті MariaDB або SQL-редакторі DBeaver. Завершуються `;`. Приклади нижче використовують таблиці з лабораторної роботи.

```sql
SHOW DATABASES;             -- список баз
USE borys;                  -- вибрати базу
SHOW TABLES;                -- список таблиць
DESCRIBE Users;             -- структура таблиці
```

**CRUD** — чотири основні операції з даними:

```sql
-- Create: додати запис
INSERT INTO Users (FullName, Email)
VALUES ('Alex Smith', 'alex@example.com');

-- Read: прочитати дані
SELECT id, FullName, Email FROM Users;
SELECT * FROM Products WHERE Price > 10000 ORDER BY Price DESC;

-- Update: змінити запис
UPDATE Users SET FullName = 'John Smith' WHERE id = 1;

-- Delete: видалити запис
DELETE FROM Users WHERE Email = 'alex@example.com';
```

`WHERE` відбирає рядки, `ORDER BY` сортує, `LIMIT` обмежує кількість результатів. Без `WHERE` команди `UPDATE` та `DELETE` діють на всі рядки таблиці.

**Не плутати:** `DELETE` видаляє рядки, `DROP TABLE` — саму таблицю разом із даними. `CREATE TABLE` створює таблицю, `ALTER TABLE` змінює її структуру.

## 5. Зв’язки, JOIN та індекси

- **Один до багатьох:** один користувач має багато замовлень. Поле `Orders.user_id` посилається на `Users.id` через зовнішній ключ.
- **Багато до багатьох:** замовлення містить багато товарів, товар входить у багато замовлень. Для зв’язку потрібна проміжна таблиця, наприклад `OrderItems`.
- **JOIN** об’єднує дані таблиць за умовою. `INNER JOIN` повертає збіги, `LEFT JOIN` зберігає всі рядки лівої таблиці, навіть без збігу справа.
- **Індекс** допомагає прискорити пошук і з’єднання таблиць, але займає місце та додає роботу під час запису. У MariaDB первинний ключ індексується автоматично.
- **Нормалізація** зменшує дублювання: дані користувача зберігають у `Users`, а в замовленні — посилання на нього.

У лабораторній таблиці `Users` і `Products` незалежні; таблиці замовлень наведені лише як приклад зв’язків.

## 6. Транзакції та ACID

**Транзакція** об’єднує кілька операцій в одну логічну дію. Наприклад, списання коштів і зарахування отримувачу мають виконатися разом.

- **Atomicity:** усі зміни транзакції виконуються разом або скасовуються.
- **Consistency:** зміни зберігають визначені правила цілісності даних.
- **Isolation:** одночасні транзакції взаємодіють відповідно до рівня ізоляції.
- **Durability:** підтверджені зміни зберігаються після збою за належних налаштувань зберігання.

У MariaDB для транзакцій зазвичай використовують таблиці **InnoDB**. `START TRANSACTION` починає транзакцію, `COMMIT` підтверджує зміни, `ROLLBACK` скасовує непідтверджені зміни даних.

## 7. Дамп та відновлення

**Дамп** — логічна копія структури й даних у вигляді SQL-команд. Команди нижче виконуються в оболонці Ubuntu через Tabby, а не всередині MariaDB.

```bash
# Зберегти базу у файл
sudo mariadb-dump borys > borys_dump.sql

# Створити іншу базу та відновити дані
sudo mariadb -e 'CREATE DATABASE borys_restored;'
sudo mariadb borys_restored < borys_dump.sql

# Перевірити відновлену таблицю
sudo mariadb --table borys_restored -e 'SELECT * FROM Users;'
```

`>` записує вивід у файл і перезаписує наявний файл, `<` передає файл на вхід команди. Для відновлення в іншу базу цей дамп створюється без `--databases`. Імпорт варто виконувати в окрему порожню базу: дамп може містити команди видалення наявних таблиць.

**Резервну копію потрібно перевіряти відновленням:** наявність SQL-файлу ще не доводить, що дані можна повернути.

## 8. Підключення та типові помилки

- Для підключення потрібні **адреса сервера, порт, користувач, пароль і права на базу**. Типовий TCP-порт MariaDB — `3306`.
- `localhost` означає поточну машину: на macOS це Mac, всередині Ubuntu — VM. Для прямого підключення DBeaver до VM використовується її IP-адреса.
- `Connection refused`: перевірити службу MariaDB (`sudo systemctl status mariadb`), адресу, порт і прослуховування мережевого інтерфейсу.
- `Access denied`: перевірити пароль, права та дозволений хост користувача MariaDB.
- `Unknown database` / `Table doesn't exist`: перевірити назву бази, таблиці та регістр літер.
- Користувач Ubuntu і користувач MariaDB — різні облікові записи. Для застосунку створюють окремого користувача бази з потрібними правами.
